# KnowledgeBase

个人网络空间安全知识库，用于记录学习过程、CTF 解题、靶机实战、技术知识、工具使用和项目实践。

## 核心原则

- 用户负责编写笔记、决定知识沉淀内容。
    
- AI 负责分类、命名、归档和整理。
    
- 用户决定知识库结构，AI 不擅自改变既定规则。
    
- 先输出整理方案，用户确认后再统一执行。
    
- 已归档笔记默认保持稳定。
    

## 目录结构

| 目录            | 用途                     |
| ------------- | ---------------------- |
| `00_Inbox`    | 新建笔记的统一入口              |
| `CTF`         | CTF 比赛题目和解题记录          |
| `BOX`         | 靶机渗透测试和提权记录            |
| `Lesson`      | 课程、教程及学习过程记录           |
| `Environment` | 软件安装、环境搭建和配置           |
| `Knowledge`   | 独立沉淀的技术知识              |
| `Tools`       | 工具功能、参数和使用方法           |
| `Projects`    | 独立项目和工程实践              |
| `Reference`   | 速查资料、Payload、命令模板和参考内容 |

### 分类约定

- CTF、BOX、Lesson 保留完整的原始学习或实战记录，不自动拆分其中的知识点。
    
- Knowledge 只收录用户主动决定独立沉淀的技术知识。
    
- Reference 侧重快速查阅，不要求系统性学习结构。
    
- Projects 用于管理有明确目标和交付成果的独立实践项目。
    

## Lesson 目录

采用「课程 → 教程 → 笔记」结构：

```
Lesson/
└── Java安全/
    └── Drun1baby_JavaSecurityLearning/
        ├── 反射机制.md
        └── 类加载机制.md
```

## 命名规范

统一格式：

```
主体_内容主题.md
主体_内容主题_具体方向.md
```

- 所有分隔符统一使用半角下划线 `_`。
    
- 不使用空格或短横线 `-` 作为分隔符。
    
- CTF 使用 `比赛名称_题目名称.md`。
    
- 命名应简洁、明确，直接体现笔记主体和内容。
    

## 图片资源

每篇 Markdown 笔记的图片放在同级同名目录中。

```
Linux_SUID提权.md
Linux_SUID提权/
└── image1.png
```

Markdown 文件和同名资源目录作为一个整体管理。

## AI 管理

本知识库使用 Codex 项目级 Skill 管理：

- `AGENTS.md`：Codex 的项目级常驻约束。
    
- `.agents/skills/knowledgebase-organizer/SKILL.md`：知识库管理工作流。
    
- `references/`：分类、命名、Git、项目管理和认知画像维护规则。
    
- `memory/cognitive-profile.md`：AI 持续维护的用户技术认知画像。
    

AI 整理时必须先检查 Git、建立整理前提交，再输出整理方案。用户确认后执行，完成后检查结果并建立整理后提交。

## Project Discovery

AI 根据知识库中的学习记录、实战证据和已有项目，发现值得开展的实践项目。

项目推荐必须说明推荐理由、已有基础、知识缺口、实施步骤和预期成果。未经用户确认，不得擅自创建或启动项目。

## 详细规范

AI 执行规则以 `.agents/skills/knowledgebase-organizer/` 中的 Skill 和参考文件为准。

本 README 面向用户阅读，不作为 AI 每次整理时必须完整读取的操作手册。
