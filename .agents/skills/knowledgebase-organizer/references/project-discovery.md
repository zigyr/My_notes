# Project Discovery

## 1. 目标

根据用户的技术认知画像，主动搜索 GitHub 上值得尝试的开源项目、功能模块或具体技术任务。

目标不是推荐大型项目让用户从头开发，而是找到与用户当前技术阶段匹配、具有实践价值的切入点。

## 2. 推荐流程

1. 读取 `memory/cognitive-profile.md`，了解用户的技术基础、兴趣和知识缺口。
2. 根据画像确定本次搜索方向。
3. 搜索 GitHub，寻找真实存在且具有实践价值的项目。
4. 综合技术匹配度、实践难度、学习价值和可操作性进行筛选。
5. 每次推荐 2～3 个方向。
6. 为每个方向制定具体的实践任务。
7. 交由用户选择。

## 3. 推荐原则

- 推荐必须以认知画像为主要依据。
- 优先选择能够补足现有知识缺口、深化已有技术方向的项目。
- 不局限于完整项目，可以推荐项目中的独立模块、功能或具体问题。
- 优先选择有实际代码、文档和可复现环境的项目。
- 关注项目的技术内容，而不单纯追逐 Star 数量。
- 不推荐明显超出当前技术基础、缺乏合理切入点的项目。
- 不为了凑够数量而推荐低价值项目；不足 2 个时说明原因。

## 4. 推荐输出

每次推荐 2～3 个方向，每个方向说明：

- **项目名称：** GitHub 项目及仓库链接。
- **实践目标：** 具体准备尝试什么。
- **推荐理由：** 与认知画像中的哪些技术基础、兴趣或知识缺口相关。
- **切入点：** 从项目的哪个模块、功能或问题开始。
- **任务拆分：** 将实践内容拆分为清晰、可执行的小任务。
- **预期成果：** 完成后能够得到什么。

推荐应具体到可以开始动手，而不是只介绍项目的用途和功能。

## 5. 用户选择

推荐完成后，由用户选择想尝试的方向。

未经用户选择：

- 不创建项目目录。
- 不生成项目源码。
- 不启动项目实施。
- 不擅自替用户决定实践方向。

用户选择后，根据其选择提供进一步的技术指导和任务执行支持。

## 6. 职责边界

Project Discovery 只负责：

- 根据认知画像发现实践机会。
- 搜索和筛选 GitHub 项目。
- 推荐具体的实践切入点。
- 拆分可执行任务。

不负责：

- 项目生命周期管理。
- 项目进度追踪。
- 项目状态维护。
- 自动创建项目目录。
- 自动提取 Knowledge。
- 根据项目长期未更新判断项目状态。
