# Note Organization

## 1. 目标

负责 `00_Inbox` 中待整理笔记的分析、分类、命名和归档。

本文件是笔记整理的主流程，具体分类、命名和迁移操作分别遵循对应参考规范。

## 2. 整理流程

### 2.1 整理前准备

1. 检查 `00_Inbox` 中的待整理笔记。
2. 调用 `git-management.md`，执行整理前备份。

### 2.2 笔记分析

1. 阅读待整理笔记，识别笔记主体和内容。
2. 调用 `note-classification.md`，确定目标分类。
3. 调用 `note-naming.md`，确定目标文件名。
4. 检查重名、相似笔记及关联资源。

### 2.3 输出整理方案

向用户展示完整方案，包括：

- 原文件名称及路径。
- 目标文件名称及路径。
- 分类和命名理由。
- 重名、相似或重复情况。
- 不确定事项。

等待用户确认，不得提前执行文件迁移。

### 2.4 执行归档

用户确认后：

1. 调用 `note-migration.md`，执行文件迁移。
2. 检查文件、图片资源和 Obsidian 双链。
3. 确认归档结果。

### 2.5 后续维护

按照以下顺序执行：

1. 调用 `cognitive-profile.md`，根据本次整理中的有效证据更新认知画像。
2. 调用 `weekly-report.md`，生成本阶段回顾并保存至 `Reports/Weekly/`。
3. 调用 `git-management.md`，提交并推送本次全部整理成果。

## 3. 执行原则

- 每次整理 Inbox 都遵循完整流程。
- 即使只有一篇笔记，也不省略方案确认。
- 没有待整理笔记时，简要说明，不执行后续流程。
- 不确定事项必须在执行前向用户确认。
- 不修改笔记正文，不擅自删除、覆盖或合并文件。
- 各环节只读取对应规范，不重复维护其他模块的规则。

## 4. 完成反馈

使用中文简要说明：

- 笔记归档结果。
- 认知画像是否更新。
- 阶段回顾的存放位置。
- Git 提交与推送结果。
