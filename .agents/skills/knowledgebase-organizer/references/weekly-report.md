# 阶段回顾规范

## 1. 目标

根据两次成功整理 Inbox 之间的新增笔记，生成阶段性学习回顾。

报告不是自然周统计，而是以实际整理时间为周期。

## 2. 统计周期

- 起点：上一次成功整理 Inbox 的时间。
- 终点：本次 Inbox 整理完成时间。
- 首次生成：以知识库建立整理机制后的首次整理时间为起点。

按实际日期命名，不要求固定七天。

## 3. 统计内容

统计本周期内进入 `00_Inbox` 的新增笔记。

区分本阶段新增内容和历史遗留事项，不将历史待处理内容计入本阶段成果。

## 4. 报告结构

### 本阶段记录

总结新增的 CTF、BOX、Lesson、Environment 及其他学习实践。

### 知识沉淀

记录用户主动创建或决定沉淀的 Knowledge。

### 关联发现

总结本阶段学习内容之间的技术联系，以及值得进一步研究的方向。

### 待处理事项

记录尚未解决的问题、待确认分类和下一阶段值得关注的内容。

## 5. 生成规则

- 每次成功整理 Inbox 后生成一份阶段回顾。
- 不设置新增笔记数量门槛。
- 没有新增记录时，也生成简洁报告，说明本阶段无新增内容。
- 历史待确认事项单独标注。
- 不根据笔记数量推断用户能力。
- 阶段点评以实际记录为依据，不进行无依据评分。

## 6. 命名与存放

固定存放目录：

```
Reports/Weekly/
```

文件命名：

```
YYYY-MM-DD_至_YYYY-MM-DD_阶段回顾.md
```

起止日期分别对应上一次成功整理时间和本次整理完成时间。

## 7. 完成标准

报告生成后，检查报告周期、统计范围、内容准确性和存放路径。

报告属于本次 Inbox 整理的交付内容，应纳入整理后的 Git 提交。
