# 认知画像维护规范

## 1. 目的

认知画像用于记录用户长期有参考价值的技术背景、实践经验、学习方向、知识缺口和学习偏好。

主要用于：

- 理解用户当前技术阶段。
- 避免重复或不合适的学习建议。
- 识别理论知识与实践经验之间的差距。
- 辅助 Project Discovery。
- 为阶段性学习建议提供依据。

认知画像不是能力评分表。

## 2. 维护文件

认知画像数据统一保存在：

```
memory/cognitive-profile.md
```

本文件负责定义画像的维护规则，实际技术信息应写入上述画像文件。

维护时：

- 画像文件不存在时，按照既定模板创建。
- 已有画像时，在原有内容基础上更新。
- 保留仍然有效的信息，避免无意义的重复记录。
- 不擅自删除有参考价值的历史记录。

## 3. 记录内容

画像主要包括：

- 技术背景与长期目标。
- 技术基础及掌握状态。
- CTF、BOX、漏洞复现和工具使用经验。
- 独立项目及实际成果。
- 当前学习方向。
- 已发现的知识缺口。
- 长期有效的学习偏好。

## 4. 技术状态

使用以下状态描述技术掌握情况：

| 状态           | 含义                       |
| -------------- | -------------------------- |
| 已接触         | 学习或接触过相关内容       |
| 已理解         | 能够解释相关原理和机制     |
| 有实践         | 有实际操作或复现经历       |
| 有独立完成证据 | 有独立完成任务或项目的证据 |
| 待确认         | 现有信息不足以判断         |

不得将“已接触”自动升级为“已掌握”。

## 5. 更新依据

画像更新以本次 Inbox 整理为依据，主要参考：

- 本次整理的原始笔记及其实际内容。
- 本次归档后的 CTF、BOX、Lesson 等实践记录。
- 用户主动沉淀的 Knowledge。
- 本次阶段回顾中的学习记录和关联发现。
- 用户在整理过程中明确表达或纠正的信息。

不得根据笔记数量、阅读次数、单次成功或失败推断能力。

区分用户明确陈述与 AI 根据实践记录作出的判断，必要时标注证据来源。

## 6. 使用原则

- 画像应反映有实际依据的技术认知和实践经历。
- 不得仅凭画像推断用户已经掌握某项技术。
- 不得将理论学习经历等同于实际操作能力。
- 不得根据单次实践结果过度评价用户能力。
- 普通笔记归档不意味着必须增加技术能力记录。
- 没有值得保留的新信息时，保持画像内容不变。

## 7. 用户控制权

用户可以随时要求查看、修正或删除画像中的内容。

用户明确纠正的信息优先于 AI 之前的判断。

用户要求不再使用某项信息时，应停止在后续分析和建议中引用该信息，并按要求处理对应记录。

## 8. 更新记录

每次实际修改画像时，在文件末尾记录：

- 更新时间。
- 更新原因。
- 新增或修正内容。
- 依据记录。

没有实际修改时，不追加更新记录。
